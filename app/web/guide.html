01 · LE BESOIN

Le besoin et les données demandées.

L’énoncé demande une API de gestion de stages, une base SQLite, des essais dans Swagger ou Postman, une image Docker et un déploiement public sur Render Free. L’interface web facilite ces mêmes opérations et constitue un complément au socle demandé.

Le modèle reste celui de l’énoncé.

Un stage a six champs. Le serveur crée l’id ; l’utilisateur fournit les cinq autres. Les statuts, les entreprises regroupées et l’avancement de l’interface sont calculés à partir des stages reçus.

Les six champs de la ressource stage
ChampRègle appliquée
idEntier positif généré par SQLite ; jamais saisi dans le corps de création.
nom_etudiantTexte obligatoire, nettoyé aux extrémités, 120 caractères au maximum.
entreprise_accueilTexte obligatoire, 160 caractères au maximum.
intitule_stageTexte obligatoire, 240 caractères au maximum.
date_debutDate calendaire au format AAAA-MM-JJ.
date_finMême format ; fin supérieure ou égale au début.

Référence : « miniProjeCloud&Microservices - Énoncé », p. 1-2. Les champs supplémentaires et les textes vides sont également rejetés.

02 · LE CONTRAT

Les méthodes et les réponses HTTP.

Le contrat HTTP réellement exposé
RequêteRésultat attenduCas d’erreur
GET /stages200 · tableau, éventuellement videListe vide acceptée
GET /stages/{id}200 · le stage demandé404 absent, 422 id invalide
POST /stages201 · stage créé et en-tête Location422 saisie invalide
PUT /stages/{id}200 · cinq champs remplacés, même id404 ou 422
DELETE /stages/{id}204 · corps de réponse vide404 ou 422

PUT est un remplacement complet.

Les cinq champs éditables sont obligatoires. Envoyer uniquement l’intitulé produit une erreur 422. Une modification partielle demanderait un contrat PATCH distinct.

Idempotent décrit l’effet.

Répéter le même PUT garde le même état. Répéter DELETE laisse la ressource absente, même si la seconde réponse est 404 après un premier 204.

03 · DE LA REQUÊTE À LA RÉPONSE

Que se passe-t-il après un clic ?

Choisissez un cas pour suivre les responsabilités du client, de l’API et de la base. Ces exemples sont explicatifs : ils n’envoient aucune requête et ne modifient aucune donnée.

Une création valide reçoit un nouvel identifiant.

Le client envoie

POST /stages
Content-Type: application/json

{
  "nom_etudiant": "Camille Démo",
  "entreprise_accueil": "Atelier Santé Démo",
  "intitule_stage": "Suivi des parcours",
  "date_debut": "2027-02-01",
  "date_fin": "2027-07-30"
}

Le serveur répond

HTTP 201 Created
Location: /stages/42

{
  "id": 42,
  "nom_etudiant": "Camille Démo",
  "entreprise_accueil": "Atelier Santé Démo",
  "intitule_stage": "Suivi des parcours",
  "date_debut": "2027-02-01",
  "date_fin": "2027-07-30"
}
  1. ClientL’interface ou Swagger envoie les cinq champs en JSON.
  2. FastAPI + PydanticLa route sélectionne l’opération et valide types, longueurs et chronologie.
  3. SQLiteL’INSERT paramétré crée la ligne dans une transaction et génère son id.
  4. RéponseL’API renvoie le stage, le code 201 et Location. L’interface recharge les données.

L’identifiant 42 illustre le parcours. En pratique, utilisez toujours celui renvoyé par votre propre POST.

04 · DES CHOIX EXPLICABLES

Un service, des responsabilités distinctes.

A

FastAPI expose ; Pydantic valide.

app/main.py définit les routes et les codes HTTP. app/schemas.py décrit les entrées et les sorties. Une requête invalide est arrêtée avant la fonction métier.

B

SQLite persiste dans un fichier.

app/database.py lie les valeurs aux paramètres SQL, ouvre une connexion par opération, valide ou annule la transaction et ferme la connexion. Le fichier conserve les stages lors d’un redémarrage local si le même fichier est réutilisé.

C

Docker rend l’exécution reproductible.

Le Dockerfile est la recette ; l’image est le paquet construit ; le conteneur est son exécution. Python, les dépendances et app/ sont embarqués. Le processus tourne avec un utilisateur non privilégié.

D

Le navigateur appelle le même service.

HTML, CSS et JavaScript sont servis par FastAPI. L’interface appelle les chemins relatifs /stages sur la même origine. Node sert aux tests ; il n’est pas nécessaire au démarrage du conteneur.

La persistance dépend aussi de l’hébergement.

Sur Render Free, le système de fichiers est éphémère : les stages SQLite peuvent disparaître à la veille, au redémarrage ou au redéploiement. Cette limite est explicitement acceptée dans l’énoncé. Seules des données fictives sont utilisées.

07 · LES QUESTIONS À MAÎTRISER

Vérifier sa compréhension.

Pourquoi une API si l’interface permet déjà de tout faire ?

L’API définit un contrat indépendant de l’écran. L’interface, Swagger ou un autre client peuvent utiliser les mêmes ressources. Le serveur conserve la validation et la gestion des données.

Qu’est-ce qui empêche une injection SQL ?

Les valeurs sont liées à des paramètres ? ou nommés, au lieu d’être concaténées au SQL. Pydantic contrôle aussi la forme des données. Cela ne remplace pas une gestion des accès pour un usage réel.

Pourquoi 422 et 404 sont-ils différents ?

422 indique que la requête ne respecte pas le schéma ou les règles, par exemple une date impossible. 404 indique qu’une ressource désignée par un identifiant valide n’existe pas.

Swagger est-il l’API ?

Swagger UI est un client web interactif construit à partir du contrat OpenAPI. FastAPI sert l’API. On peut fermer Swagger et continuer à appeler l’API depuis l’interface ou un autre client.

Que conserve SQLite après un arrêt ?

Le fichier conserve les transactions validées s’il est réutilisé. Supprimer un conteneur sans stockage durable ou redéployer sur le disque éphémère de Render peut supprimer ce fichier. SQLite et la durabilité du disque sont deux questions différentes.

Peut-on dire que c’est une architecture de microservices ?

Le projet est un service web unique organisé en modules, déployé dans un conteneur. Les modules ne sont pas des microservices autonomes. Un découpage distribué nécessiterait plusieurs services indépendamment déployables et des besoins qui le justifient.

Une couverture Python de 100 % prouve-t-elle l’absence de bugs ?

Non. Elle indique que les instructions et branches mesurées ont été exécutées. La pertinence des assertions, les essais HTTP, les tests JavaScript et les parcours visuels apportent d’autres éléments de confiance.

Que faudrait-il changer pour gérer de vrais stages ?

Ajouter une authentification, des autorisations par rôle, un stockage durable avec sauvegardes, une journalisation adaptée et une politique de protection des données. Le projet actuel est public et utilise uniquement des données fictives.
